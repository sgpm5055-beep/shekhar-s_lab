Method: cross-referenced every shared symbol (enums, Repo methods, state fields, env vars, exceptions, builders) between the three JSON designs; verified claimed v1.0 survivals against the committed dossier (docs/plans/2026-10-08-eligibility-agent.md C1–C21; docs/design/*.md — endpoint constants, stage gate, C11 regexes, half-up round_to_nearest_1000, checkpointer/tracing, FrozenClock all present as claimed); machine-verified every pinned numeric constant (HMAC vectors, 15 annuity values, EMI branches, displayed-FOIR 0.360569/0.301270 — all self-consistent per design; the floor-vs-half-up rounding divergence is real: 367,000 vs 368,000 and 1,276,000 vs 1,277,000 on the same raws). ## [blocker] status×code legality (pending_verification)
**Issue:** Design 1's code_legal() and the schema.sql code_legality CHECK require code IS NULL for status='pending_verification', and design 2's bureau node writes code=None on timeout — but design 3's failure matrix and tests (test_timeout_and_locks item 18, _recompute matrix) pin status='pending_verification' WITH code='SUREPASS_FAILURE'. As specified, the persist update violates the DB CHECK in Supabase and the MemoryRepo code_legal predicate, and the two sections' tests assert opposite values.
**Fix:** Pick code=None for pending_verification (the design-1/design-2 majority; MSG_PENDING_VERIFICATION in `label` already carries the human message). Update design 3's failure-matrix row and test 18 to assert code is None; keep PAN_LOCKED for requests arriving during the lock.

Fix the method count.

## [major] cache contents — derived facts vs raw pointers
**Issue:** Design 2's pan_comprehensive reuse branch reads rec.derived (Identity.model_validate(rec.derived)) and its call branch writes put_pan_record(…, derived=identity.model_dump(…)); its quick bureau reuse reads get_score_cache(pan_hash) -> ScoreFacts directly. Design 1's rows (PanRecordRow/ScoreCacheRow) have NO derived column (pointers-only, per PRD 5.4 and its explicit decision voiding the v1.0 derived-jsonb contract), and its own nodes-contract requires fetch_raw(storage_key) + adapter re-parse on every hit. The specified graph code cannot be written against the specified schema, and storing derived facts freezes them against adapter fixes — exactly what 5.4 forbids.
**Fix:** All reuse branches: raw = repo.fetch_raw(row.storage_key); facts = adapter(raw). Adapters must accept raw envelope dicts (not only SurePassResult), including score-facts-from-a-report-envelope (score_cache.source='report' points at the report object). Delete derived= kwargs and ScoreFacts-returning cache getters from design 2's pseudocode and its interfaces_consumed.

## [major] timeout reconciliation gate vs test 18

## [major] admission guard architecture + refusal precedence

**Fix:** Adopt design 1's pure-guard + node-executes split (it is what keeps the decision tables unit-testable and the lock acquire atomic) and its QK/FL ordering as normative; rewrite design 2's admission-node signature and design 3's guard-order expectation. Add a parametrized precedence test: cap-reached + recent-NTC full check refuses PAN_DAILY_CAP, not WARN_NTC_RECENT.
