# Audit: coherence — internal cross-consistency of the five section designs (no external sources used)

Finding counts: {'blocker': 7, 'major': 16, 'minor': 6}

## [blocker] (b) checks-row lifecycle
**Issue:** Three conflicting write models for the checks row: graph expects the API layer to pre-insert a 'pending' row and nodes to call repo.save_check(CheckRecord) as an UPSERT; policy/schema specify the admission node inserts CheckRow(status='running') then persist uses update_check(CheckPatch); tests mention a 'started' status. schema.sql CHECK(status in ('running','ok','pan_invalid','refused','error')) rejects 'pending'/'started', and surepass_calls.check_id FK requires the row to exist before the first SurePass call.
**Fix:** Canonicalize the policy model: admission node calls repo.insert_check(CheckRow(status='running')) before any SurePass call; persist/persist_refusal call update_check with status+refusal_code+billed+counted_against_cap+lc_view+internal+langsmith_run_id in ONE patch (satisfies refusal_code_iff_refused). Delete save_check/CheckRecord and all 'pending'/'started' references; graph nodes adopt CheckRow/CheckPatch; main.py crash handler uses record_check_error (update-else-insert status='error'), added to the Repo protocol.

## [blocker] (b) repo protocol parity
**Issue:** The method set used by guards/nodes/routes/tests does not equal the protocol: put_cache (policy) vs upsert_cache (graph/tests); log_surepass_call(SurePassCallRow) vs log_surepass_call(**kw incl. called_at) (graph) vs insert_surepass_call(**kw, no called_at) (tools CallLogSink) vs insert_surepass_call(row) (tests); lenders_for_pincodes->LenderRow dataclass (policy) vs get_active_lenders_for_pincodes (graph) vs active_lenders_for_pincodes->list[GatedLender] (tests) vs tools' separate LenderRow TypedDict; insert_consent(ConsentRow)->None (policy) vs insert_consent(**kw)->str (graph/tests); latest_full_check_for_opportunity vs latest_ok_full_check_for_opportunity; record_check_error (main), list_checks/list_surepass_calls/upsert_lender (tests) are absent from the protocol.
**Fix:** db/repo.py is the single registry. Freeze: insert_consent(ConsentRow)->None (admission generates id via new_id()), put_cache(CacheRow), log_surepass_call(SurePassCallRow), surepass_calls_for_check, lenders_for_pincodes(Collection[str])->list[LenderRow(id,name,active,criteria,hard_cutoffs,matched_pincodes)], latest_full_check_for_opportunity, get/insert/update_check, quick_checks_used_today; ADD record_check_error, list_checks, list_surepass_calls, upsert_lender to the protocol with MemoryRepo+SupabaseRepo impls. Rename every call site in graph nodes, tools LenderSource, main.py and tests to exactly these; delete tools' LenderRow TypedDict and import the dataclass.

## [blocker] (e) LLM DI seam
**Issue:** FakeLLMs do not satisfy the graph's protocol: graph defines StructuredLLM.__call__(messages: Sequence[BaseMessage], *, config) -> RankingProposal/FinalRecommendation; tests define RankLLM = Callable[[RankContext], Ranking] and import RankContext/FinalizeContext from eligibility_agent/graph/llm.py, a module no section creates; tests' default fake behavior needs ctx.cutoffs/ceilings/gated_lenders that cannot be recovered from rendered messages; tests also expect a merged Ranking(ranked, accepted: list[str], dropped) that conflicts with graph's RankingProposal(ranked) + Ranking(accepted: list[RankedLender], dropped) split.
**Fix:** Create graph/llm.py as the seam owner: RankContext/FinalizeContext (kind, applicant, affordability/cutoffs, ceilings, gated_lenders, ranking, flags, attempt, validation_errors), RankLLM=Callable[[RankContext], RankingProposal], FinalizeLLM=Callable[[FinalizeContext], FinalRecommendation]. Nodes build the context; the production adapter (make_structured_llm wrapper) renders prompts from the context and calls with_structured_output. Keep state's RankingProposal/Ranking split (tests derive id lists via [r.lender_id ...]); update fakes, evals/run.py and the prompts renderers to this one definition.

## [blocker] (e) GraphDeps/build_graph
**Issue:** Three incompatible build signatures: graph build_graph(kind, deps: GraphDeps{repo,surepass,rank_llm,finalize_llm,prompts,now}, *, checkpointer=None); tests GraphDeps{repo,surepass,rank_llm,finalize_llm,clock,live_calls_enabled,checkpointer} with build_graph(kind, deps); API main.py build_graph(kind, repo=..., surepass=..., rank_llm=..., finalize_llm=..., checkpointer=...) with no GraphDeps, no prompts, no now, plus an undefined make_openai_llms factory that conflates prompt refs with LLM construction.
**Fix:** Graph's signature is canonical. main.py lifespan: prompts=load_prompts(settings); rank/finalize via make_structured_llm(RankingProposal|FinalRecommendation, model=settings.openai_model); deps=GraphDeps(repo, surepass, rank_llm, finalize_llm, prompts, now=utcnow); build_graph(kind, deps, checkpointer=cp). Tests fixture adds prompts=local_prompts() and now=clock.now, drops live_calls_enabled (admission reads deps.surepass.calls_enabled) and moves checkpointer to the build kwarg. Delete make_openai_llms / make_rank_llm / make_finalize_llm.

## [blocker] (a)+(b) admission guards & AdmissionDecision
**Issue:** Three admit_* signatures: policy admit_quick_check(repo, *, lc_id, pan_hash, consent, refresh, surepass_live, now); graph calls it without consent and with live_enabled=...; tests expect admit_quick_check(repo, clock, *, ..., live_calls_enabled). Consent is gated twice (node pre-check AND guard Q1/F1). AdmissionDecision shapes conflict: policy carries cache_row (a full CacheRow INCLUDING raw payload — graph explicitly forbids payload in the decision) + refresh_available_at; graph reads decision.cache_fetched_at/cache_expires_at which policy lacks; tests expect a field named 'billed' not 'billed_expected'; admit_full_check has lc_id that graph never passes.
**Fix:** Freeze: admit_quick_check(repo, *, lc_id, pan_hash, consent, refresh, surepass_live, now: datetime) and admit_full_check(repo, *, lc_id, pan_hash, opportunity_id, opportunity_stage, consent, refresh, surepass_live, now). AdmissionDecision(admission, refusal_code, billed_expected, counts_against_cap, quick_checks_used_today, cache_fetched_at, cache_expires_at) — cache_row removed (nodes re-read via get_cache). Graph admission passes consent=state['consent'] (guard is the SOLE consent gate; node drops its pre-check) and surepass_live=deps.surepass.calls_enabled; tests assert billed_expected and pass now=clock.now().

## [blocker] (c) cache freshness / schema_version
**Issue:** policy.is_cache_fresh requires derived['schema_version'] == DERIVED_SCHEMA_VERSION, and schema.sql's derived contract includes schema_version:1 — but the graph pull nodes write derived={'identity':..., 'score'|'report':...} with NO schema_version (graph's own derived-contract interface omits it too). Every cache row the service writes is judged permanently stale: zero cache hits ever, every repeat check re-billed, PRD 6.4 and tests 2/8 fail silently.
**Fix:** pull_score/pull_report write derived={'schema_version': guards.DERIVED_SCHEMA_VERSION, 'identity': ..., 'score'|'report': ...}; cache-hit readers validate subkeys only (extra key ignored). Update the graph section's derived-contract interface text to include schema_version.

## [blocker] (f) PAN hashing — two owners, two formulas
**Issue:** hash_pan is defined in BOTH config.py (sha256(f"{salt}:{PAN}"), keyword-only salt) and policy/guards.py (sha256(salt + PAN), positional, no colon). Both claim to be 'THE canonical hasher'; the tests section itself references both formulas (test_config asserts the colon variant, its main.py expectation states the colon-less one). Mixed imports silently split the pan_cache/cap/opportunity keyspace — cache misses and broken once-per-opportunity gate with no error.
**Fix:** Single definition in eligibility_agent/config.py: hash_pan(pan, *, salt) = sha256(f"{salt}:{normalize(pan)}").hexdigest(). Delete policy.guards.hash_pan (normalize_pan/PAN_RE may stay in policy or move alongside); all sections import config.hash_pan; align tests' expectation text to the colon formula.

## [major] (e) SurePass client seam
**Issue:** Protocol named SurePassClientProtocol (graph) vs SurePassClient (tools) vs SurePassLike (tests); concrete class LiveSurePassClient (tools) vs HttpSurePassClient (main.py) vs SurePassClient(token, live) used as a concrete class in tests; liveness property live_enabled (graph) vs calls_enabled (tools); result type SurePassResult with .raw and success always bool (tools, validation envelope raises) vs SurePassResponse with .body and success: bool|None returned (graph/tests); check_id is a per-call parameter only in tools' methods.
**Fix:** tools/surepass.py is canonical: Protocol SurePassClient {calls_enabled: bool; pan_comprehensive(check_id, pan); experian_score(check_id, *, name, mobile, pan); experian_report(...)} -> SurePassResult(.raw); concrete LiveSurePassClient(token, live, sink, base_url, http); validation envelope raises SurePassValidationError while the audit row records success=NULL. Rename graph's protocol import and live_enabled reads, main.py's constructor, and tests' class references; nodes pass state['check_id'].

## [major] (f) surepass_calls logging & billed ground truth
**Issue:** Two owners: tools' client logs every HTTP attempt via CallLogSink (incl. transport failures, http_status=None) and policy mandates an immediate update_check({'billed': True}) per call with persist recomputing billed from surepass_calls_for_check; graph states the OPPOSITE ('the client does NOT log to the DB — nodes do'), has validate_pan/pull nodes call repo.log_surepass_call, and persist derives billed from state pan_called/bureau_called, never reading the log. Policy's compute_billed/compute_bureau_called helpers are orphaned under the graph design.
**Fix:** Client+sink own logging (keeps the one-row-per-attempt guarantee on exception paths and fake/live parity): delete repo.log_surepass_call calls from graph nodes (keep pan_called/bureau_called state flags for routing); persist computes billed=policy.compute_billed(repo.surepass_calls_for_check(check_id)) and counted via policy.compute_counted_against_cap, making policy's formulas the single implementation; drop the per-call billed flip (surepass_calls is the crash-reconciliation source, as policy's own risk note says). Update the graph section's client-contract text.

## [major] (f) LcView builder & refusal strings
**Issue:** Two builder APIs and two REFUSAL_MESSAGES maps with DIFFERENT texts: output/lc_view.py defines build_lc_view(state, RedactionContext)/build_error_lc_view + REFUSAL_MESSAGES set A (scrub-verified); graph nodes call build_lc_view(**kwargs) and a build_refusal_view that output never defines; policy/guards.py ships REFUSAL_MESSAGES set B with different wording and claims output consumes it verbatim. Graph's build_refusal_view signature also lacks cache timestamps, so the CACHE_FRESH_NO_REFRESH refusal could not carry refresh_available_at that API and tests/test_refresh assert.
**Fix:** output/lc_view.py is sole owner of builders and all LC-facing strings: build_lc_view(state, RedactionContext(quick_checks_remaining_today, cache_fetched_at, cache_expires_at)) covering ok/pan_invalid/refused branches, build_error_lc_view, REFUSAL_MESSAGES (API's texts), PAN_INVALID_LINE, MANUAL_REVIEW_LINE. Delete policy's REFUSAL_MESSAGES and graph's build_refusal_view; redact AND persist_refusal call build_lc_view with ctx populated from decision-carried cache timestamps.

## [major] (f) leak-regex triplication with semantic drift

## [major] (b) tools function contracts

## [major] (e) checkpointer construction & invoke mechanism

## [major] (e) FakeSurePassClient constructor parity
**Issue:** One class, two contracts: tools' FakeSurePassClient takes a single Scenario per endpoint with FakeCall(endpoint, check_id, body) and AssertionError on unconfigured endpoints; tests construct it with Mapping[PAN -> EnvelopePair] per endpoint, expect FakeSurePassCall(endpoint, pan, payload) and KeyError on unmapped PANs (needed for multi-PAN tests like retry-after-fix).

## [major] (f)+(c) quick_checks_remaining_today / cache-field owner
**Issue:** Computed in two places with diverging semantics: graph redact (admission-carried used-count + will-count; None for kind='full') vs policy persist (re-queries quick_checks_used_today and re-reads get_cache AFTER redact, and computes remaining for full checks too — contradicting graph/API/tests' null-for-full).
