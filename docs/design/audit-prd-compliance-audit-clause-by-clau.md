# Audit: prd-compliance-audit (clause-by-clause gate over PRD v1.0 sections 3-13 + field-map adapter fidelity, across the five section designs)

Finding counts: {'blocker': 2, 'major': 14, 'minor': 9}

## [blocker] pan_cache freshness contract (FIXED rules 6.4/6.5)
**Issue:** policy/guards.is_cache_fresh requires derived.schema_version == DERIVED_SCHEMA_VERSION (and db/schema.sql documents derived with schema_version:1), but the graph section's pull_score/pull_report write derived={'identity','score'|'report'} with NO schema_version, and use payload keys {'pan','score'|'report'} vs schema.sql's {'pan_comprehensive','experian_score'|'experian_report'}. Built as specified, every cache row reads permanently stale: no cache hit ever occurs, every repeat check re-bills SurePass and burns the LC cap — FIXED rules 4 and 5 (and tests 2/6/8) are nullified at runtime.
**Fix:** Ratify the db/policy derived+payload contract as authoritative; change graph nodes.py pull-node cache writes to include schema_version=1 and the schema.sql key names (or drop the version check with owner sign-off); add a unit test that round-trips a pull-node CacheRow through policy.is_cache_fresh.

## [blocker] checks-row lifecycle / surepass_calls FK (rules 6.3, 8.1 logging)
**Issue:** Three incompatible owners for the early checks row: graph's main.py contract says the API pre-inserts status='pending' before invoke; policy says the admission node inserts status='running'; the API section's actual main.py inserts nothing. schema.sql's surepass_calls.check_id FK requires the parent row before the first call log, and the schema CHECK allows 'running' but not 'pending'. Graph persist also calls repo.save_check (UPSERT) while db Repo offers insert_check (raises on duplicate) + update_check. MemoryRepo enforces no FK, so the whole pytest suite stays green while production 500s on the first billed call and loses the call audit.
**Fix:** Single owner: admission node inserts the checks row (status='running') before any SurePass call per the policy write-pattern; API route does not pre-insert; replace graph's save_check with insert_check+update_check (or define save_check as exactly that pair in db/repo.py); unify the status vocabulary; make MemoryRepo.log_surepass_call assert the parent check row exists to restore FK parity in tests.

## [major] LLM / dependency-injection seam (graph-owned per local context)
**Issue:** Graph defines GraphDeps(repo, surepass, rank_llm, finalize_llm, prompts, now) with StructuredLLM.__call__(messages, *, config) and in-node prompt rendering; the tests section compiles against a different seam — GraphDeps(repo, surepass, rank_llm, finalize_llm, clock, live_calls_enabled, checkpointer), RankLLM=Callable[[RankContext],Ranking], FinalizeLLM=Callable[[FinalizeContext],FinalRecommendation], and a graph/llm.py module the graph section never designed; the API section expects make_openai_llms(model, temperature, api_key, prompt refs/tags) which graph does not provide (it provides make_structured_llm(schema, *, model, timeout)). Ranking shapes also differ (graph RankingProposal+Ranking(accepted,dropped) vs tests' single Ranking(ranked, accepted, dropped)). PRD 12's 'FakeLLM implementing with_structured_output' is satisfied only at the seam, which is fine, but only one seam can exist.
**Fix:** Ratify the graph section's seam verbatim (local context assigns ownership there): rewrite eligibility_agent/testing/fake_llm.py, tests/conftest.py, test_llm_misbehavior.py and evals/run.py run_one against message-based StructuredLLM fakes and the RankingProposal/Ranking split; delete RankContext/FinalizeContext; add a thin make_openai_llms wrapper in graph/build.py or have main.py call make_structured_llm twice.

## [major] SurePass client protocol + audit-log ownership (PRD 8.1)
**Issue:** Tools (layout owner): methods take check_id, the client logs every HTTP attempt itself via CallLogSink.insert_surepass_call, property calls_enabled, result type SurePassResult. Graph: methods without check_id, client explicitly 'does NOT log' (nodes call repo.log_surepass_call(..., called_at=...)), property live_enabled, type SurePassResponse. Tests: fake keyed per-PAN mapping with FakeSurePassCall(endpoint, pan, payload) and KeyError on unmapped PAN vs tools' per-endpoint Scenario + AssertionError. PRD 8.1 places 'log every call' in the client contract; exactly one surepass_calls row per attempt must hold, and the policy_consistency evaluator reads the fake's log.
**Fix:** Ratify the tools protocol (per-call check_id, client-side logging through a sink satisfied by Repo, calls_enabled); graph nodes drop their own log_surepass_call calls and pass check_id; tests adopt tools' FakeSurePassClient and constants; unify the result type name and sink method name with db/repo.

## [major] Repo protocol (db-owned)
**Issue:** At least three divergent Repo definitions: db/policy (insert_check/update_check/get_check/put_cache/log_surepass_call(row)/surepass_calls_for_check/lenders_for_pincodes→LenderRow/latest_full_check_for_opportunity, MemoryRepo(clock=Callable)); graph (insert_consent(**kw)→str, get_cache(*, kw-only), upsert_cache, save_check(CheckRecord) UPSERT, log_surepass_call(**kw incl. called_at), get_active_lenders_for_pincodes); tests (insert_surepass_call(row), list_surepass_calls, list_checks, upsert_lender, active_lenders_for_pincodes→list[GatedLender], latest_ok_full_check_for_opportunity, MemoryRepo(clock: Clock)). The API section additionally calls repo.record_check_error, which no Repo variant defines.
**Fix:** db/repo.py is the single owner: publish one Protocol merging the needs (add record_check_error or route API error handling through update_check; add list_checks/list_surepass_calls/seed_lender as MemoryRepo-only test helpers); mechanically rename all consumers; mypy --strict over tests will enumerate the stragglers.

## [major] Admission guard seam (rule 6 enforcement surface)
**Issue:** Three admit_* signatures: policy admit_quick_check(repo, *, lc_id, pan_hash, consent, refresh, surepass_live, now); graph calls it without consent and with live_enabled=deps.surepass.live_enabled; tests expect (repo, clock, *, lc_id, pan_hash, refresh, live_calls_enabled). AdmissionDecision also differs: graph expects cache_fetched_at/cache_expires_at scalars and states 'Decision must NOT contain the cache payload — metadata only', while policy's AdmissionDecision carries the full CacheRow including raw payload — contradicting graph's requirement and brushing against acceptance 13's no-raw-path review.
**Fix:** Ratify policy's guards as owner with one signature (keep the consent param; one live flag sourced from client.calls_enabled); replace cache_row in AdmissionDecision with cache_fetched_at/cache_expires_at (+ is_ntc if needed) so no raw payload rides the decision; graph and tests adapt.

## [major] Consent request schema (PRD 9.1 'consent must be literally true')
**Issue:** API section: consent: StrictBool — false flows into the graph and persists a CONSENT_MISSING refusal row (its test_consent_matrix asserts 200+refusal). Tests section: consent: Literal[True] — false/absent → 422 and CONSENT_MISSING unreachable via API (matches graph's stated assumption). Both sections ship a tests/test_api_auth_and_validation.py with opposite assertions; PRD 9.1's letter supports Literal[True]/422.
**Fix:** Owner decision required; default to the PRD letter (Literal[True] → 422, CONSENT_MISSING retained as a guard-level defense that is unit-tested directly), and rewrite the API section's consent matrix test + its 422-vs-refusal table row; if the refusal-row variant is preferred instead, amend PRD 9.1 and the tests section.

## [major] opportunity_stage validation (PRD 9.2 ASSUMPTION enum)
**Issue:** API validates opportunity_stage against the OpportunityStage StrEnum at the schema (unknown value → 422), while the tests section pins 'unknown stage string passes schema (str) but refuses STAGE_TOO_EARLY at graph level'; policy models stages as a plain tuple with fail-closed stage_allows_full_check. Representation (StrEnum vs tuple) and rejection surface (422 vs refusal row) conflict.
**Fix:** Adopt the API split — schema 422 for values outside the ASSUMPTION enum, policy ordering (STAGE_TOO_EARLY) for valid-but-early — with the enum living only in policy/guards.py as the single FulCRM swap point (open item 1); fix the tests section's unknown-stage cases.

## [major] PAN hashing (rule 6.4 cache keying)
**Issue:** Three formulas/locations claim canonical: policy/guards.hash_pan = sha256(salt + normalized PAN); config.hash_pan (API, 'THE canonical hasher') = sha256(f'{salt}:{PAN}') — a different preimage; tests expect config.hash_pan == sha256((salt+pan).utf8) (no colon). Salt env is PAN_HASH_SALT (policy/API) vs PAN_SALT (tests conftest + README). Divergent digests break the shared 30-day PAN-level cache, consent/check correlation, and the once-per-opportunity gate.
**Fix:** One function, one formula, one env name, one module (recommend config.hash_pan with the colon-free concatenation policy and tests already share); policy re-exports or imports it; delete the duplicate and align README/.env.example.

## [major] Postgres checkpointer (PRD 4 stack + 7.3)
**Issue:** Graph (seam owner) mandates sync PostgresSaver over a manually built psycopg pool (autocommit, dict_row, prepare_threshold=None), Supabase session pooler, and a dedicated non-PostgREST 'checkpointer' schema because checkpoint blobs carry the raw PAN and raw_payloads; the API lifespan instead uses AsyncPostgresSaver.from_conn_string(DATABASE_URL) — the exact from_conn_string pattern graph documents as broken behind poolers — with no schema isolation, and awaits graph.ainvoke while graph specifies sync invoke in a threadpool (all deps sync). Env name also differs (CHECKPOINTER_DB_URL vs DATABASE_URL vs policy's SUPABASE_DB_URL).
**Fix:** main.py lifespan must call graph's make_postgres_checkpointer and run graph.invoke via run_in_threadpool (drop ainvoke/AsyncPostgresSaver); keep the isolated checkpointer schema (it is a data-leak control tied to acceptance 13); settle one env var name in config.py.

## [major] Error boundary for mid-run failures
**Issue:** Graph and tools specify SurePassError/RuntimeError escaping the graph → HTTP 502 with checks.status='error'; the API section returns HTTP 200 with a deterministic review-outcome LcView (status 'ok') for every exception including timeouts, plus a best-effort error row — and the tests section pins the 200 path. Also asyncio.wait_for cannot actually cancel a sync bureau call running in a thread, so the timeout semantics are advisory.
**Fix:** Owner-signed single policy: either 502+error row (graph/tools) or 200-review (API/tests); update the losing sections' text and tests; whichever wins, keep checks.status='error' ops alerting, and ratify that a crashed run's LcView.status='ok' (if 200-review wins) is acceptable or introduce a distinct presentation.

## [major] Leak scrub regex + evaluator reuse (FIXED redact rule 7.3 / rule 6.10)
**Issue:** output/lc_view.py (owner) ships bureau regex with plural superset (bureaus?) and 300-899 regex (?<!\d)(?<!\d[.,])[3-8]\d{2}(?!\d)(?![.,]\d) which drops 'Rs.736'; the tests/evals sections re-implement a different SCORE_RE (?<![\d,.])[3-8][0-9]{2}(?![\d,.]) that KEEPS 'Rs.736' (weaker than the FIXED 'standalone 300-899' intent) and tests pin 'bureaus differ' as KEPT — an assertion that fails against the owner's plural regex and would pressure an implementer to weaken it. The API section explicitly mandates evaluators import LEAK_PATTERNS, yet evals/evaluators.py and tests/helpers.py redefine the patterns.
**Fix:** Single definition in output/lc_view.py; no_leak evaluator and test helpers import LEAK_PATTERNS/line_leaks; delete the contradictory 'bureaus differ' KEPT vector and align the vector tables; owner ratifies the plural strengthening (safe — strengthens, never weakens, the FIXED rule).

## [major] Shared Pydantic models (graph/state.py leaf contract)
**Issue:** Consumers compile against fields state.py lacks or contradicts: tools' adapters emit BureauScore.ntc_reason and BureauReport.open_account_count and name the account model OpenAccountMissingEmi (graph: UnreportedEmiAccount, neither extra field); graph's blanket _Frozen extra='forbid' clashes with tools' required extra='ignore' on HardCutoffs (an unknown jsonb key must skip-with-warning, not hard-fail validation of every lender); tests expect Affordability.ceilings dict + existing_emi_estimated and a merged Ranking; the API section demands LcView with str ISO timestamps, int LoanRange, and pan_aadhaar_link_issue: Literal[True]|None vs graph's datetime/float/bool|None; BAND_ORDER is declared in three modules (state.py, adapters.py, and tests expect it in lenders.py).
**Fix:** Ratify state.py as single source and reconcile the union: add ntc_reason + open_account_count, pick one account-model name, set HardCutoffs extra='ignore', keep graph's assessments but expose a ceilings accessor for prompts/tests, adopt the API's stricter Literal[True] and int LoanRange at the LcView boundary, export BAND_ORDER once from state.py.

## [minor] billed-flag crash truthfulness (rule 6.3 accounting)
**Issue:** Policy mandates update_check({'billed': True}) immediately after every surepass_calls log so a mid-run crash leaves billing truthful; neither the graph nodes nor the tools client implement that write — graph recomputes billed only at persist, so a crash after a bureau call leaves billed=false on the row (surepass_calls remains the only evidence).

## [minor] Tracing wiring (PRD 11 tags/metadata)
**Issue:** Two mechanisms are specified for the same obligations: graph/tracing.py (invoke_config builds tags/metadata; route-level finish_trace patches admission:<mode> + billed/counted via Client.update_run) vs the API section inlining its own RunnableConfig (extra metadata keys, langsmith_run_id in metadata) and delegating the admission tag to the admission node's span and the billed/counted patch to the persist node. **Fix:** main.py uses graph/tracing.py's new_run_id/invoke_config/finish_trace verbatim; remove the API section's inline config and node-level patch expectations; keep the additive lead/opportunity metadata only if folded into invoke_config.

## [minor] Auth when SERVICE_API_TOKEN unset (section 9 auth line)

**Fix:** Owner sign-off; keep the README warning and supabase hard-fail; consider the alternative (401/503 on /checks when token unset) since acceptance 13 can be read as requiring only /health + refusal behavior once authenticated.

## [minor] Rounding convention (8.4 ceiling vs LcView range)
