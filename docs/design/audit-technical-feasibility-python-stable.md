## [blocker] checkpointer lifecycle (graph/build.py vs main.py lifespan)
**Issue:** The API section's lifespan uses `AsyncPostgresSaver.from_conn_string(settings.database_url)`, which contradicts the graph section's manual-pool design and reintroduces the exact pooler bug the graph section documents: verified in source (checkpoint-postgres 3.1.2, both sync and aio) that from_conn_string hardcodes `Connection.connect(..., autocommit=True, prepare_threshold=0, row_factory=dict_row)` — prepared statements from the first execution, no way to pass prepare_threshold=None. Behind Supabase's transaction pooler (6543) this fails ('prepared statement _pg3_n does not exist'; official docs: transaction mode does not support prepared statements); it also opens a single shared AsyncConnection (serializing all checkpoint IO) and bypasses the dedicated-schema isolation (no search_path). Additionally the three sections name three different env vars for the same DSN: CHECKPOINTER_DB_URL (graph), DATABASE_URL (API), SUPABASE_DB_URL (db/schema.sql comment).
**Fix:** Single owner: graph section's make_postgres_checkpointer is the correct, verified pattern — `ConnectionPool(conninfo=url, min_size=1, max_size=5, open=True, kwargs={'autocommit': True, 'prepare_threshold': None, 'row_factory': dict_row})`; `PostgresSaver(pool)` (verified: Conn = Connection[DictRow] | ConnectionPool); `saver.setup()` once at lifespan start; main.py consumes (saver, pool) and closes the pool at shutdown. If async is preferred, `AsyncPostgresSaver(AsyncConnectionPool(..., kwargs=same))` is equally valid — never from_conn_string against Supabase. Note verified: AsyncPostgresSaver's sync methods only work from a non-event-loop thread (InvalidStateError guard + run_coroutine_threadsafe), so pick one invocation style (sync PostgresSaver + run_in_threadpool(graph.invoke) is simplest with all-sync deps). Use the session pooler URI (:5432, aws-0-<region>.pooler.supabase.com) or direct connection; standardize on one env var name (suggest CHECKPOINTER_DB_URL).

## [blocker] cross-section DI seam (will not compile or run when merged)
**Issue:** The five sections declare mutually incompatible versions of the shared contracts; mypy --strict will reject the merge and some drifts are silent-corruption bugs: (1) hash_pan defined twice with DIFFERENT formulas — policy: sha256(salt + PAN) vs config: sha256(f'{salt}:{PAN}') — divergent digests split the PAN cache/cap accounting depending on importer; (2) env names PAN_HASH_SALT (policy/API) vs PAN_SALT (tests conftest/README); (3) three Repo protocols: db section (insert_check/update_check/log_surepass_call/lenders_for_pincodes, positional) vs graph (save_check UPSERT, get_cache keyword-only, get_active_lenders_for_pincodes) vs tests (upsert_cache/insert_surepass_call/list_checks/active_lenders_for_pincodes/upsert_lender/record_check_error); (4) three build_graph/GraphDeps shapes (graph: GraphDeps(repo,surepass,rank_llm,finalize_llm,prompts,now) vs tests: +clock,+live_calls_enabled,+checkpointer vs API: build_graph(kind, repo=..., checkpointer=...) kwargs); (5) SurePass client protocol: tools takes check_id per call and logs via CallLogSink vs graph's check_id-free methods with node-side logging vs policy's 'tool wrapper logs and flips billed'; (6) Ranking model: graph's RankingProposal(ranked=...)/Ranking(accepted: list[RankedLender]) vs tests' Ranking(ranked=..., accepted: list[str]); (7) LcView field types: cached_at datetime (graph) vs ISO str (API), LoanRange float vs int; (8) API route's initial state omits langsmith_run_id/rank_attempts/etc. that the graph's initial-state contract requires (mostly safe via total=False, but the checks row loses langsmith_run_id under the API variant).
**Fix:** Before implementation, ratify one authoritative seam file set and mechanically reconcile the other sections: graph/state.py (models incl. ONE Ranking/RankingProposal pair and ONE LcView with datetime fields serialized by model_dump(mode='json')), config.py (ONE hash_pan — pick the salt:PAN form — and ONE env table), db/repo.py (ONE Repo protocol; adopt the db section's names and add the few extras tests need: list_checks, record_check_error, upsert_lender on MemoryRepo only), tools/surepass.py (adopt the tools section's check_id-per-call + CallLogSink version; delete the graph section's variant), graph/build.py (ONE GraphDeps including checkpointer passed to build_graph, now/clock unified as `now: Callable[[], datetime]`). Running `mypy --strict` over eligibility_agent + tests will enumerate the remainder — that is the acceptance gate the PRD already demands.

## [major] checkpointer schema isolation (Supabase/Supavisor)
**Issue:** The design's PII isolation relies on appending `options=-csearch_path%3Dcheckpointer` to the pooler URI. Managed poolers commonly reject or silently drop the `options` startup parameter ('unsupported startup parameter in options'); I could not confirm that Supavisor session mode reliably honors it, and the current langgraph-checkpoint-postgres README contains no such Supabase/search_path instruction (the design cites it as README guidance). If the parameter is dropped, checkpoint tables containing raw PAN + raw bureau payloads land in `public` — exposed via PostgREST — with no error.
**Fix:** Make the isolation server-side and pooler-agnostic: create a dedicated role for the checkpointer DSN and `ALTER ROLE checkpointer_svc IN DATABASE postgres SET search_path = checkpointer;` (applies on every connection regardless of options support); keep the URI options trick only as belt-and-braces on direct connections. Add a startup assertion after saver.setup(): execute `SELECT current_schemas(false)` (or to_regclass('public.checkpoints') IS NULL) and fail fast if the first schema is not 'checkpointer'.

## [major] checkpoint deserialization security (langgraph-checkpoint-postgres 3.x)
**Issue:** New since the design was written: the checkpoint-postgres 3.x README (verified on the 3.1.2 page) carries a security directive — 'Set LANGGRAPH_STRICT_MSGPACK=true or pass an explicit allowed_msgpack_modules list when creating your checkpointer. This restricts checkpoint deserialization to known-safe types, preventing code execution if the database is compromised.' The design configures neither. This matters doubly here because CheckState stores custom Pydantic models (Identity, BureauScore, BureauReport, Ranking, FinalRecommendation, LcView) in checkpoint blobs alongside the raw PAN: without strict mode the DB is an RCE vector; with strict mode enabled but no allowlist, checkpoint round-trip of those models will be rejected.
**Fix:** Set LANGGRAPH_STRICT_MSGPACK=true in production env (document in .env.example/README) AND allowlist the state-model module(s) (allowed_msgpack_modules including 'eligibility_agent.graph.state') when constructing the saver/serde per the langgraph-checkpoint serde docs. Add one test that round-trips a fully-populated CheckState through InMemorySaver (same serde) with strict mode on, so the allowlist cannot silently rot.

## [major] tests/pyproject [tool.pytest.ini_options]
**Issue:** `filterwarnings = ["error::pytest_socket.SocketBlockedError"]` is invalid and suite-breaking: verified in pytest-socket source that `class SocketBlockedError(RuntimeError)` — not a Warning subclass. Python's warnings machinery (and pytest's filter parsing) requires a Warning subclass as the category, so every test errors when the filter is applied; the whole no-network suite fails before any assertion runs.
**Fix:** Delete the line. pytest-socket raises SocketBlockedError as an exception at the call site; no warnings filter is needed or possible. (--disable-socket and --allow-unix-socket flags verified present in 0.8.1 and the --allow-unix-socket rationale for TestClient's AF_UNIX socketpair is correct.)

## [minor] graph/build.py make_structured_llm — stale rationale, moved default
**Issue:** Two facts changed under the design: (1) verified in langchain-openai 1.6.x source that with_structured_output's default method is now 'json_schema' (docstring: "method default changed from 'function_calling' to 'json_schema'"); (2) verified in OpenAI's structured-outputs guide that strict mode NOW supports maxLength, minLength, pattern, format, minItems, maxItems (except fine-tuned models), plus all-fields-required + additionalProperties:false. So the design's justification for method='function_calling' ("strict json_schema rejects maxLength/maxItems that FinalRecommendation carries") is false as of 2026. The pinned method itself still works — 'function_calling' remains a supported literal with its own code path — and constraints are then enforced by Pydantic at parse time exactly as designed.
**Fix:** Keep the explicit method= pin (mandatory now that the library default moved), but rewrite the comment: either (a) stay on method='function_calling' with rationale 'constraint violations surface as parse exceptions absorbed by the node retry loop', or (b) prefer method='json_schema', strict=True so OpenAI enforces the maxLength/maxItems/≤2-alternates constraints server-side (fewer retries) while validate_final still does the business checks. Do not strip constraint keywords — no longer necessary.

## [minor] pyproject version pins — ecosystem crossed several majors
**Issue:** Several design pins now resolve across major versions with behavior/compat risk: pytest>=8.3 resolves to pytest 9.1.1; mypy>=1.14 resolves to mypy 2.4.0; fastapi 0.142.2 pulls starlette 1.7.0; 'pin langgraph-checkpoint-postgres accordingly' names no major but the line is now 3.x (2.x → 3.0 breaking bump Oct 2025); supabase has a 3.0.0a1 prerelease on PyPI. Also checkpoint-postgres installs bare psycopg — macOS/CI without libpq need the binary extra; and zoneinfo('Asia/Kolkata') needs tzdata on slim images.
**Fix:** Adopt the verified pins in version_pins (upper-bound every direct dependency at the next major; add psycopg[binary] and tzdata explicitly). pytest-socket 0.8.1 (2026-08-19, requires pytest>=7) installs cleanly with pytest 9.

## [minor] httpx constraint vs supabase
**Issue:** supabase 2.32.0 requires httpx>=0.26,<0.29 (verified metadata); the tests section declares dev dep 'httpx>=0.27' with no cap. uv will still resolve to 0.28.1 today because of supabase's cap, but the uncapped spec invites breakage if supabase is ever removed from an environment that keeps httpx. Note: langsmith 0.14 depends on the separate 'httpx2' package (>=2,<3) — different distribution name, coexists with httpx 0.28; starlette 1.7's TestClient accepts either.
**Fix:** Pin httpx>=0.27,<0.29 in the dev group to match supabase's window; no action needed for httpx2 (transitive via langsmith).

## [minor] main.py _run_check timeout semantics
**Issue:** `asyncio.wait_for(graph.ainvoke(...), timeout=90)` cancels the asyncio task but cannot stop sync nodes already running in executor threads (SurePass HTTP call, persist). After a timeout the route writes checks.status='error' and returns the review LcView, yet the abandoned thread can later complete persist/save_check and overwrite the row to status='ok' with an LcView nobody received; the bureau spend also completes despite the 'timeout'.
**Fix:** Make the terminal update guarded: persist should UPDATE ... WHERE status='running' (or save_check must refuse to downgrade/overwrite a terminal 'error' row), so the late thread cannot flip an already-errored check; log when the guard fires. Document that GRAPH_TIMEOUT_SECONDS bounds the HTTP response, not the spend.

## [minor] evals/datasets.py create_examples call shape
**Issue:** The design uses the legacy parallel-list form `create_examples(inputs=[...], outputs=[...], dataset_id=...)`. Verified in langsmith 0.14.4 source: still accepted (supported legacy kwargs: inputs/outputs), but the signature is now keyword-only with the primary form `examples=[{'inputs': ..., 'outputs': ...}]` (behavior changed in 0.3.11; ValueError if both forms are mixed).
**Fix:** Use the current form: `client.create_examples(dataset_id=..., examples=[{'inputs': {k: ex[k] for k in (...)}, 'outputs': ex['expected']} for ex in examples])` — one object per example, no mixing with legacy kwargs.

## [minor] mypy --strict practicality in graph/build.py
**Issue:** `bind = lambda fn: functools.partial(fn, deps=deps)` is untyped: `fn` infers as Any, every node becomes Any-typed, and partial's typeshed overloads don't model keyword binding — under --strict this silently erases the node-signature checking the design wants (and E731 is already acknowledged). Runtime is fine (verified: langgraph's RunnableCallable introspects inspect.signature, which resolves partials, and injects config by the parameter NAME 'config').
**Fix:** Replace with a typed closure factory: `NodeFn = Callable[[CheckState, RunnableConfig], StateUpdate]; def bind(fn: Callable[[CheckState, RunnableConfig, GraphDeps], StateUpdate], deps: GraphDeps) -> NodeFn: def node(state: CheckState, config: RunnableConfig) -> StateUpdate: return fn(state, config, deps); node.__name__ = getattr(fn, '__name__', 'node'); return node` — keeps the param named 'config' (required for injection) and full type checking. The GraphT alias is fine as written: CompiledStateGraph is Generic[StateT, ContextT, InputT, OutputT] with PEP 696 defaults (verified), and mypy 2.4 supports TypeVar defaults, so `StateGraph[CheckState]` also type-checks.

## [minor] README run command
**Issue:** README section 6 says `uv run uvicorn eligibility_agent.main:app` but main.py deliberately exports no module-level `app` (factory-only, per the API section's own decision) — the documented command fails at import with 'Attribute "app" not found'.
**Fix:** README must use the factory form the API section specifies: `uv run uvicorn 'eligibility_agent.main:app_factory' --factory --port 8080`.

## [minor] model configurability guard (config.py / make_structured_llm)
**Issue:** gpt-4.1 is verified live (model page lists gpt-4.1 / gpt-4.1-2025-04-14 with function calling and structured outputs 'Supported'; temperature works on this non-reasoning family). But OPENAI_MODEL is configurable, and switching it to a gpt-5-family reasoning model makes the hardcoded temperature=0 raise a 400 from the API (reasoning models reject temperature).
**Fix:** In make_structured_llm, only pass temperature for non-reasoning model ids (e.g., omit the kwarg unless the model matches the gpt-4.x family), or document in .env.example that OPENAI_MODEL must be a temperature-capable model; keep gpt-4.1 as the verified default.
